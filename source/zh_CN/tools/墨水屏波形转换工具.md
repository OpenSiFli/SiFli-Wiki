# EPD 波形转换工具使用说明

## 1. 概述

本工具集用于将墨水屏（E-Paper）厂商提供的私有格式波形文件，转换为固件可直接加载的标准格式 `.bin`。

支持两种输入格式（自动识别）：

| 输入格式 | 识别方式 | 典型来源 |
|---------|---------|---------|
| **厂商格式** (vendor) | 文件头是 ASCII 名字 + 3072B 私有 header | 原厂 `.bin` 文件 |
| **标准格式** (standard) | 文件头 magic = `0xE9D7AB1E` | 本工具链输出的 `.bin` |

## 2. 工具清单

| 工具 | 脚本 | exe | 用途 |
|------|------|-----|------|
| **vendor_bin_to_cbin** | `vendor_bin_to_cbin.py` | `vendor_bin_to_cbin.exe` | **主工具**：bin → bin 直转（推荐） |
| **vendor_bin_to_xlsx** | `vendor_bin_to_xlsx.py` | `vendor_bin_to_xlsx.exe` | bin → xlsx（查看中间格式） |
| **waveform_xlsx_to_cbin** | `waveform_xlsx_to_cbin.py` | `waveform_xlsx_to_cbin.exe` | xlsx → bin / C 数组 |

转换路径：

```
厂商 bin ──→ vendor_bin_to_cbin.exe ──→ 标准 bin (推荐, 直转)
厂商 bin ──→ vendor_bin_to_xlsx.exe ──→ xlsx ──→ waveform_xlsx_to_cbin.exe ──→ 标准 bin (xlsx 查看/编辑路径)
标准 bin ──→ vendor_bin_to_cbin.exe ──→ 标准 bin (无损复读)
```

## 3. 快速使用

### 3.1 厂商 bin → 标准 bin（最常用）

```powershell
.\vendor_bin_to_cbin.exe "厂商波形.bin" -o "输出标准bin.bin"
```

实际示例：

```powershell
.\vendor_bin_to_cbin.exe "520_VSH202_HRA902_B082A05_TC.bin" -o "520_VSH202_HRA902_B082A05_TC_new.bin"
```


```powershell

```

```powershell
.\waveform_xlsx_to_cbin.exe "Waveform.xlsx" -o "out.bin"
```

## 4. 命令行参数

### 4.1 vendor_bin_to_cbin.exe

| 参数 | 必填 | 说明 |
|------|------|------|
| `<input.bin>` | ✅ | 输入 bin（自动识别厂商/标准格式） |
| `-o, --output <file>` | ✅ | 输出标准 bin 路径 |
| `--mode N` | ❌ | 只处理单个 mode_index（默认处理所有有效 mode） |
| `--all-modes` | ❌ | 包含全 constant 的 mode（mode 0-4 等空壳也写入） |
| `--version 0x12` | ❌ | 指定 bin 格式版本（默认 0x12） |

### 4.2 vendor_bin_to_xlsx.exe

| 参数 | 必填 | 说明 |
|------|------|------|
| `<input.bin>` | ✅ | 输入 bin（自动识别格式） |
| `<output.xlsx>` | ✅ | 输出 xlsx 路径（将被覆盖） |
| `--mode-index N` | ❌ | 只转换单个 mode_index |
| `--all-modes` | ❌ | 包含全 constant 的 mode |

### 4.3 waveform_xlsx_to_cbin.exe

| 参数 | 必填 | 说明 |
|------|------|------|
| `<input.xlsx>` | ✅ | 输入 xlsx |
| `-o, --output <file>` | ✅ | 输出路径（.bin / .c） |
| `--value-map "-15:2,0:0,15:1"` | ❌ | 电压→2-bit 映射 |
| `--version 0x12` | ❌ | 覆盖版本号 |

## 5. 文件格式详解

### 5.1 厂商 bin 格式（已逆向）

```
offset 0        : ASCII 名字 (28 bytes, 如 "520_VSH202_HRA902_B082A06_TC")
offset 28..3071: 厂商私有 header (mode 表、温度系数、14 条目录条目等)
offset 3072..  : 波形数据区
                  16 modes × 17 temp_blocks × 51 frames
                  每帧 64 bytes = 256 × 2-bit 值
```

- 2-bit 值只出现 {0, 1, 2}，天然对应标准 bin 值
- mode 0-4 基本全 constant（全 0 / 全 +15V / 全 -15V），无真实波形
- mode 5-15 是有效波形（每个 mode 有 500-800+ 个 real frame）

### 5.2 标准 bin 格式（generate_bin_data 输出）

```
Header (136 bytes):
  offset 0    : magic       = 0xE9D7AB1E
  offset 4    : version     = 0x12
  offset 8..135: mode_entry[16] (每 mode 8 bytes: num_blocks + first_table_offset)

每个 mode 的 body:
  [table entries] 每个 temp_block 16 bytes: tmin + tmax + frame_count + wave_offset
  [wave data]      所有帧连续排列，每帧 64 bytes

每个 64-byte 帧:
  byte layout: bit7-6=pixel0, bit5-4=pixel1, bit3-2=pixel2, bit1-0=pixel3
  解码: vals.append((b>>6)&3)
```

### 5.3 2-bit 值 ↔ 电压 映射

| 2-bit 值 | 电压 | xlsx 值 |
|---------|------|--------|
| 0 | 0V | 0 |
| 1 | +15V | 15 |
| 2 | -15V | -15 |

厂商 bin 和标准 bin 的 2-bit 值完全一致，无需转换。

## 6. xlsx 模板格式

```
Config sheet:
  row 1: key | value | description
  row 2: version | 18 | Bin format version
  row 4: sheet_name | mode_index
  row 5+: GC16 | 0
         DU    | 1
         ...

数据 sheet (如 GC16):
  row 1: [temperture | Old gray scale | New Gray Level | Frame | 1 | 2 | ... | N]
  row 2..257: tmin | 0 | 0 | fc | v1 | v2 | ... | vN   (第一个 temp_block)
  row 258..513: tmin | 0 | 1 | None | ...
  ...
```

- 每个 temp_block 256 行（old_gray 0-15 × new_gray 0-15）
- 温度只在每个 block 第一行填一次
- frame_count 只在每个 block 第一行填一次
- 电压值为 -15 / 0 / 15

### Config sheet mode 映射

`waveform_xlsx_to_cbin.py` 现在优先从 Config sheet 读取 `sheet_name → mode_index` 映射。
这允许自定义 sheet 名（如 DUMMYb → mode 10），不再受限于固定映射表。

## 7. mode 编号参考

| mode | 标准名 | 说明 |
|------|--------|------|
| 0 | GC16 | 16 灰全局更新 |
| 1 | DU | 快刷新（高温帧数多、低温帧数少） |
| 2 | GC4 | 4 灰全局更新 |
| 3 | INIT | 初始化 |
| 4 | - | dummy（厂商 bin 里全 constant） |
| 5 | GL16 | 16 灰 |
| 6 | A2 | A2 模式 |
| 7 | DU4 | 4 灰快刷新 |
| 8 | GLR16 | 16 灰 |
| 9 | GLD16 | 16 灰 |
| 10-15 | - | 厂商 bin 有效波形（厂商自定义） |

## 8. 常见问题

### Q1: 输出 bin 比厂商 bin 小很多？
厂商 bin 把 16 个 mode 全塞了（含 5 个全 constant 的空壳）+ 3KB 私有 header。本工具只保留有效 mode。固件加载时也会跳过空壳 mode。加 `--all-modes` 可强制包含。

### Q2: 为什么 mode 0-4 被过滤了？
它们基本全是 constant（整 mode 就是一个固定电压），无任何可产生灰度效果的波形数据。固件 header 里这些 mode 的 `num_blocks=0`，加载时自动跳过。

### Q3: 标准 bin 的 DU/DU4 模式帧数为什么不固定？
DU 模式高温帧短、低温帧长是正常设计（32.bin：mode 1 从 74→58→44→32→...→14 帧递减）。xlsx 里取最大帧数做列数，短 block 后面补 0。

### Q4: Windows PowerShell 中文乱码？
脚本输出里中文可能显示成乱码（GBK 控制台），但不影响 ASCII 输出和文件内容。所有关键日志（[OK]、size、modes）都是 ASCII。

### Q5: openpyxl MemoryError？
大 xlsx（>6MB）全量加载可能爆内存。推荐走 bin→bin 直转路径（`vendor_bin_to_cbin.exe`），跳过 xlsx。

## 10. 验证方法

### 固件加载验证（最权威）
烧录输出 bin 到固件，看启动日志里是否出现 `Custom EPD wave table validation OK`。

### 端到端数据验证
```powershell
python vendor_bin_to_cbin.exe "vendor.bin" -o "output.bin"
python vendor_bin_to_cbin.exe "output.bin" -o "roundtrip.bin"
# 如果 output.bin == roundtrip.bin，说明数据零误差
```

### Header 快速检查
```powershell
python -c "import struct; d=open('out.bin','rb').read(); m,v=struct.unpack_from('<II',d,0); print(f'Magic=0x{m:08X}, Version=0x{v:02X}')"
# 期望: Magic=0xE9D7AB1E, Version=0x12
```
